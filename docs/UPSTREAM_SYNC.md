# Upstream Synchronization

Use candidate branches; never mutate the accepted baseline in place.

1. Verify provenance and regenerate source, profile, declaration-entity, behavioral-block, dependency, and generated-input diffs.
2. Build production and diagnostic C oracles and run their baseline suites.
3. Identify invalidated atomic-unit dossiers, Zig mappings, representation-difference records, generated artifacts, internal traces, and evidence states.
4. Port affected dependency-closed responsibilities under `docs/ENGINEERING_PROCESS.md` and rerun targeted traces, assurance, then full native gates.
5. Test old/candidate/Zig database continuation and migration behavior.
6. Confirm production artifacts still contain zero C objects.
7. Atomically update baseline, checksums, generated artifacts, and sync report.

Security fixes are applied to the Zig implementation before the project claims the candidate baseline. Oracle code is evidence, never an execution path in the product.
